# Slayer feature: scope

Status: step 1 (task panel, locations, Shortest Path buttons) is built. Steps 2 to 5 are not started.

## What it does

1. You get a slayer task. A side panel opens on that task.
2. The panel lists the task's monster variants. For "Abyssal demons" that means the normal demon, the Greater abyssal demon (superior) and the Abyssal Sire.
3. Each variant expands to show:
   - its locations, each with a travel time
   - its notable drops, with icons and drop rates
4. Clicking **Go** on a location asks the Shortest Path plugin to path you there. **Go to nearest** passes every location and lets Shortest Path pick the closest one.
5. **Gear up** works out the best outfit you own for the chosen variant. It opens it as a temporary bank tag tab laid out like your equipment screen, so you can withdraw it in one pass.

## How each part works

### 1. Detecting the task

- **Recommended:** add `@PluginDependency(SlayerPlugin.class)` and inject `SlayerPluginService`. It provides:
  - `getTask()`
  - `getTaskLocation()` (Konar's assigned area)
  - `getRemainingAmount()` and `getInitialAmount()`
  - `getTargets()` (the matching NPCs currently loaded)
- **Fallback, with no dependency:** read the game state directly and listen with `onVarbitChanged`.
  - Task id: varp 395. Remaining amount: varp 394. Original amount: varp 4258. Konar area: varp 2096.
  - Task names come from DB table 113. Area names come from DB table 115.
  - Boss tasks: when the task id is 98, read varbit 4723 and look it up in DB table 116.
- The core plugin's `Task` enum is package-private, so variant data has to come from our own dataset.

### 2. Data: variants, locations, drops

- Ship a JSON snapshot inside the plugin, generated by a script run at build time.
  - Runtime wiki calls are allowed on the plugin hub, but they need a `warning=` in the plugin properties ("submits your IP to a third party").
  - A bundled snapshot avoids that and works offline.
- **Variants:** the wiki's `infobox_monster` bucket has a `slayer_category` field, so we can query "all monsters for task X". The osrs-dps-calc repo has a working script that queries this bucket.
  - Superiors and bosses (e.g. Abyssal Sire) aren't always tagged with the task. They need a small hand-maintained extras list.
- **Locations:** each location needs a name plus one or more `WorldPoint`s to path to.
  - It's unconfirmed whether the wiki exposes spawn coordinates in a machine-readable form. Assume we hand-curate a target point per location, at least for the common tasks.
  - This is the most labour-intensive part.
- **Drops:** the wiki has drop tables. Keep only the notable drops: uniques, high-value items, and anything rarer than a set threshold. Store item id, rate and quantity.
- **Not verified:** the wiki couldn't be reached from this session, so no live query was run.

### 3. Pathing with Shortest Path

The Shortest Path plugin documents a cross-plugin API, in `docs/Cross-plugin-communication.md` of Skretzo/shortest-path.

```java
Map<String, Object> data = new HashMap<>();
data.put("target", location.getPoints());      // one WorldPoint, or a collection: it picks the cheapest
eventBus.post(new PluginMessage("shortestpath", "path", data));
```

- **Go to nearest:** pass every location's points in one `target` collection.
- **Travel times:** send `query` messages. The `result` reply includes `cost` in game ticks, which we show next to each location.
- **Done:** send `clear` when the task completes or the user cancels.
- **Requirements:** a target can carry item requirements, e.g. a dusty key or a slayer helm. Shortest Path then routes via the bank first if needed.
- Shortest Path stays optional. If it isn't installed, the buttons are hidden, or they fall back to RuneLite's world map hint arrow.

### 4. Gear recommendation (ties into the bank part)

- **GearScape:** no public API or documented integration was found, and gearscape.net couldn't be reached from here. We shouldn't build on it unless you know of an API.
- **Use the OSRS Wiki DPS calculator's data instead.** The weirdgloop/osrs-dps-calc repo has:
  - `equipment.json`: about 5,100 items with bonuses, speed and slot
  - `monsters.json`: about 2,900 monsters with defence stats, attributes, weaknesses and variants
  - Bundle a pinned snapshot of both.
- **Calculation, done locally:**
  1. Candidates = items in your bank, inventory and worn equipment. The bank is only readable while it's open, so we cache its contents each time you close it.
  2. For each style (melee, ranged, magic), pick the best item per slot by expected DPS against the variant. Handle two-handed weapons and set effects as special cases: slayer helm/black mask, salve amulet, void, and dragonhunter/demonbane weaknesses.
  3. Show DPS per style and recommend the highest.
- **Licence:** porting the wiki calculator's formulas means our plugin becomes GPL-3.0. Writing our own simplified max-hit/accuracy maths avoids that.
- **Verify button:** RuneLite core's `WikiDpsManager` already sends worn gear to the wiki DPS calculator. We can do the same with the recommended loadout and monster, so you can check our numbers. This is a network call, so it needs the hub `warning=`.
- **Bank tie-in:** reuse the existing Layout code. **Gear up** writes a temporary tag `slayer-<task>` with the outfit placed in equipment-screen positions, then opens that tab.

## Existing plugins that overlap

Several plugin-hub plugins already cover much of this. They're worth trying before we build it:

- **Slayer Suite** (pricecheckgg/slayer-suite): task card with drop odds and gear, ranked spots, routing, and a check that you have what you need in the bank. The closest match to this whole idea.
- **All-In Slayer** (danieljglover/AIO-Slayer-Assistant): monsters, locations and loadouts from owned gear. Uses Shortest Path.
- **Slayer Sensei** and **SlayerAIO**: locations plus gear advice. Both use Shortest Path.
- **SlayerBIS**, **Slayer Best in Bank** and **Slayer Loadout**: best gear from your bank for the current task.

Building our own still makes sense if you want it combined with the combat-tab organiser, or just to have it the way you like.

## Build order

1. **Task panel and locations.** Detect the task, show variants and curated locations, add Go / Go to nearest via Shortest Path. Start with about 20 common tasks. This is the smallest version that's useful.
2. **Drops.** Generate notable drops from the wiki snapshot.
3. **Travel times.** Show the cost from Shortest Path `query`.
4. **Gear from bank.** Local DPS ranking and the Gear up tag tab.
5. **Wiki DPS verify button.**

## Decisions

**Data: bundled snapshot.**
- Ship a snapshot generated from the wiki and refresh it with each plugin release.
- A later "Refresh from wiki" option, off by default, can fetch newer drop data.
- The one network call is the optional "Check in wiki DPS calculator" button. It only runs when clicked.

**Slayer masters: cover them all.**
- Every task from every master gets data.
- Konar: show only the locations in her assigned area, read from `getTaskLocation()`.
- Krystilia: show only Wilderness locations, and send Shortest Path `avoidWilderness=false` for that route only.
- Other masters: hide the Wilderness-only locations by default.
- Hand-curated pathing spots are done first for tasks that most masters assign.

**Gear up includes task items and supplies.**
- **Required items.** If you own a slayer helmet, it replaces the nose peg, earmuffs, facemask and spiny helmet.

  | Task | Item |
  | --- | --- |
  | Gargoyles | rock hammer |
  | Desert lizards | ice cooler |
  | Rockslugs | bag of salt |
  | Mutated zygomites | fungicide spray |
  | Aberrant spectres | nose peg |
  | Banshees | earmuffs |
  | Dust devils | facemask |
  | Basilisks, cockatrices | mirror shield |
  | Wall beasts | spiny helmet |
  | Killerwatts | insulated boots |
  | Brine rats | boots of stone |

- **Teleport:** the Shortest Path `result` lists the transports it used. If the fastest route uses a teleport item you have in the bank, Gear up adds that item.
- **Supplies:** food and potions for the chosen combat style, taken from what you have tagged as supplies.
